title: MCP

`cliver-core` includes an MCP client that supports **stdio** and **streamable HTTP** servers.
Connect a client to an `AgentCore` and its tools become available to the model.

```python
from cliver_core import AgentCore
from cliver_core.mcp import MCPClient

client = MCPClient.from_discovery()
agent = AgentCore(bindings, builtin_tools=[...], mcp_client=client)
```

## Discovery

`MCPClient.from_discovery()` reads CLIver-local MCP configuration — `~/.cliver/mcp.json`,
project `.cliver/mcp.json`, and drop-in configuration files. Pass `extra=` to add servers
programmatically.

Call `agent.chat(..., mcp_servers=["server-name"])` to advertise and allow only that subset for
one call. `None` (the default) exposes every configured server; an empty list exposes none. A
tool from an unselected server cannot be executed even if the model calls it by name. The client
starts lazily (and idempotently) before tools are gathered, so the first turn already sees MCP
tools.

## Tool Naming

MCP tools are advertised as `mcp__<server>__<tool>`. They share the same execution path as
builtin tools — including permission categories and events. A server's self-declared
`readOnlyHint` annotation maps to the `SAFE` category; it is a hint, never a permission
boundary. Override individual tools with `safety_overrides=`.

## Session Pooling

By default every tool call opens an ephemeral session: a stdio server starts a subprocess per
call, and streamable HTTP dials a new client per call. A **streamable-http** server can instead
keep a pool of open sessions:

```json
{
  "mcpServers": {
    "docs": {
      "transport": "streamable-http",
      "url": "https://example.com/mcp",
      "headers": {"Authorization": "Bearer ${DOCS_TOKEN}"},
      "session_pool_size": 4
    }
  }
}
```

- `session_pool_size=N` is the **maximum number of concurrent tool calls** for that server.
  Sessions are leased exclusively: up to N calls run at once, and a further call waits for an
  idle session instead of dialing again.
- Sessions open lazily on the first pooled call. `start()` discovery, prompts, and resources
  stay ephemeral.
- A call that raises (transport failure) evicts its session: it is closed and the next call
  opens a replacement. An MCP `is_error` result is tool-level and keeps the session.
- `session_pool_size` is supported on streamable-http only. Discovery drops the key from stdio
  entries with a problem report; `create_adapter` raises `ValueError`. Absent or `0` keeps the
  ephemeral behavior.
- `close()` stops the pool and closes its sessions — leased ones included, which is how an
  in-flight call is cancelled. Drain calls first. A pool belongs to its `MCPClient` and its
  event loop.

## Lifecycle

`start()` is single-flight: concurrent callers share one discovery pass, and a cancelled waiter
does not cancel discovery for the others. A server that fails to start is logged and skipped —
the rest still connect. `close()` cancels an in-flight start, closes every adapter exactly once,
and is safe to call concurrently.

`add_server()` before `start()` defers the connection until that start; afterwards it connects
immediately. The agent **never closes an injected client** — whoever constructs it closes it,
after the agent's calls are drained. Like the rest of the agent, a client belongs to one event
loop.

## Prompts and Resources

MCP prompts and resources are read **on demand** — never registered as model tools and never
listed at startup:

```python
prompts = await client.list_prompts()
messages = await client.get_prompt("server-name", "args-prompt", {"city": "Paris"})

resources = await client.list_resources()
contents = await client.read_resource("server-name", "demo://document")
```

This keeps the core a pure reader: cataloguing, formatting, caps, and whether to send MCP
content to the model are application concerns.
