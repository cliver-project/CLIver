title: CLI Application
---

`cliver` is the CLI application layered on `cliver-core`. It provides CLIver's config-directory
and skill-discovery conventions, and runs either one agent task per invocation or an interactive
REPL session.

The CLI is published to PyPI as `cliver`; install it with `pip install cliver`. From a
repository checkout, `uv run cliver` runs the same command after `make init`. The examples below
use `uv run cliver`; with the PyPI install, use `cliver` directly.

## Usage

```bash
# endpoint and model come from flags or CLIVER_* variables
export CLIVER_MODEL=deepseek-v4-flash
export CLIVER_PROVIDER=deepseek
export DEEPSEEK_API_KEY=...

uv run cliver "Summarize the last three commits as release notes."

# approve mutating tool calls (Write, Bash, ...) without prompting
uv run cliver --yes "Read packages/cliver-core/pyproject.toml and list its dependencies."

# run an explicit skill; --cwd selects the project root for skill discovery
uv run cliver --skill live-check --cwd ~/projects/demo "Run the live check."
```

Safe tools (`Read`, `LS`, `Grep`, `TodoRead`, `TodoWrite`) run without approval. ASK tools
(`Write`, `Bash`, `Exec`, `WebFetch`) go through the SAFE/ASK gate: the CLI prompts on an
interactive terminal and denies them in a non-interactive session unless `--yes` is passed.

Piped stdin works as the prompt:

```bash
git diff | uv run cliver --yes "Review this diff for correctness problems."
```

The first positional word is a subcommand only when it is exactly `image`,
`video`, `audio`, `tts`, or `asr`. Anything else is a chat prompt — including a single quoted
prompt such as `cliver "image classification is hard"`. For a chat prompt whose first word is
a command name, prefix it with `chat`:

```bash
uv run cliver chat "image classification is hard" --yes
```

### Media commands

Media commands read their model from the JSON configuration and do not need a chat model:

```bash
uv run cliver image "a red panda on a skateboard"
uv run cliver video "a drone shot over a misty forest"
uv run cliver audio "Hello from CLIver."          # tts is an alias
uv run cliver asr ./meeting.mp3 --language zh
```

Generated files are saved in the current directory as
`<command>-<timestamp>-<n>.<ext>` — for example `image-20261124-153012-0.png` — and each saved
path is printed. `--out DIR` writes into another directory. `asr` prints the transcript and
saves nothing.

Add the purpose under `models` in `{config_dir}/config.json` (or the project file
`<cwd>/.cliver/config.json`):

```json
{
  "models": {
    "image": [{"model": "qwen-image-plus", "provider": "qwen-image"}],
    "video": [{"model": "<video-model>", "provider": "dashscope"}],
    "tts": [{"model": "<tts-model>", "provider": "minimax"}],
    "asr": [{"model": "<asr-model>", "provider": "minimax"}]
  }
}
```

A missing purpose is one error line naming the config file, never a traceback. One-shot media
commands run the primary configured binding; other model parameters (`size`, `voice`,
`response_format`, …) belong in that entry's `params`.

### Interactive REPL

Run `cliver` with no prompt on a terminal to start the REPL:

```bash
uv run cliver --yes
```

```
cliver REPL (deepseek-v4-flash) — /help for commands, /exit to quit.
cliver> Summarize the agent loop.
...
cliver> Now do the same in one sentence.
...
cliver> /exit
```

Each turn streams the answer to stdout and keeps the conversation, so follow-up questions see
the earlier turns. Tool activity still prints to stderr through the event logger, and ASK tools
use the same permission gate — pass `--yes` to approve them, or answer the prompt per call.
Commands:

| Command | Effect |
|---|---|
| `/help` | Show the command list |
| `/clear` | Forget the conversation and start fresh |
| `/image <prompt>` | Generate an image into the current directory |
| `/video <prompt>` | Generate a video into the current directory |
| `/audio <text>`, `/tts <text>` | Synthesize speech into the current directory |
| `/asr <file\|url> [--language zh]` | Transcribe audio and print the text |
| `/exit`, `/quit`, `exit`, `quit` | Leave the REPL (Ctrl-D also works) |

Media commands use the running agent's bindings (including same-purpose fallbacks) and print a
`[media] ...` progress line on stderr. Their results do not enter the conversation history, and
a missing model or a failed request is reported without ending the session.

Ctrl-C at the prompt clears the line; Ctrl-C during a turn cancels that turn and keeps the
session alive. The REPL requires both stdin and stdout to be terminals, so redirecting either
one falls back to one-shot mode.

### Configuration

| Setting | Flag | Environment |
|---|---|---|
| Model | `--model`, `-m` | `CLIVER_MODEL` |
| Known provider brand | `--provider` | `CLIVER_PROVIDER` |
| Any compatible endpoint | `--base-url` | `CLIVER_BASE_URL` |
| Wire protocol | `--protocol` (`openai` / `anthropic`) | `CLIVER_PROTOCOL` |
| API key | — | `CLIVER_API_KEY`, else the brand's variable |

The brand's conventional key (`DEEPSEEK_API_KEY`, `MINIMAX_API_KEY`, `GLM_API_KEY`, …) is
used when `CLIVER_API_KEY` is unset. `{config_dir}/.env` is loaded at startup without
overriding variables already in the process environment, so `~/.cliver/.env` is a convenient
place for keys. The file uses simple `KEY=VALUE` lines: blank lines and `#` comments are
ignored, an `export` prefix is allowed, and surrounding quotes are stripped from a value. No
variable expansion or multi-line values.

The CLI validates the chat binding at startup and builds the provider before the first model
call. A missing model, endpoint, or key is one error line naming both the flag and the
environment variable (for example `--provider` / `CLIVER_PROVIDER`), never a traceback.
`cliver --help` lists the environment variables. Any OpenAI- or Anthropic-compatible endpoint
needs a non-empty key; for a local server that needs no auth, set `CLIVER_API_KEY` to any
placeholder value.

Use `--provider` for a brand with a default endpoint, or `--base-url` for anything else
(Ollama, vLLM, a gateway). `--max-iterations` bounds the agent loop (default 50).

`CLIVER_BASE_URL` does not imply a protocol: `CLIVER_PROTOCOL` defaults to `openai`. When you
point at an Anthropic-compatible path — for example DeepSeek's `https://api.deepseek.com/anthropic`
— also set `CLIVER_PROTOCOL=anthropic`. A mismatch surfaces as an HTTP 404, and the CLI prints
the endpoint and protocol it used to make the cause obvious.

## System One and Tool Selection

A System One decision model is configured through `CLIVER_SYSTEM_ONE_*` variables, and
`CLIVER_SELECTOR=on` turns on decision-model ranking of tools and skills. Both are disabled by
default; selection also requires a configured System One model. The variables and tuning knobs
are documented under [System One](../core-concepts/system-one/#configuration-in-the-cli).

## Config Directory

The application resolves its config directory in this order:

1. `CLIVER_CONF_DIR`
2. `%APPDATA%/cliver` on Windows
3. `~/.cliver`

## Skill Sources

Skills are discovered from eight sources, with later sources overriding earlier ones by name:

1. Builtin skills shipped with the application
2. `{config_dir}/skills`
3. `~/.agents/skills`
4. Project-local `.cliver/skills`
5. Project-local `.agent/skills`
6. Project-local `.claude/skills`
7. Project-local `.gemini/skills`
8. Project-local `.qwen/skills`

The application ships four builtin skills: `brainstorm`, `write-plan`, `execute-plan`, and
`wbs-planner`.

## Workspace Development

```bash
make init     # install both packages
make test     # run the workspace test suite
```

The application's discovery code lives in `packages/cliver` and delegates parsing, validation,
and activation to `cliver-core`'s `SkillManager`.
