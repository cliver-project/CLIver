title: AgentCore Python API
---

`AgentCore` is the embeddable engine behind CLIver. Import it from `cliver_core` and drive it
with `chat()`, `stream()`, or `run_skill()`.

## Quick Example

```python
import asyncio

from cliver_core import AgentCore, ModelBindings, presets
from cliver_core.tools import discover_builtin_tools


async def main():
    agent = AgentCore(
        ModelBindings(llm=presets.deepseek(api_key="...")),
        builtin_tools=discover_builtin_tools(),
    )

    async for chunk in agent.stream("Analyze sales.csv"):
        if chunk.content:
            print(chunk.content, end="", flush=True)

    await agent.aclose()


asyncio.run(main())
```

## Methods

### `await agent.chat(user_input, **options) → CLIverResponse`

Non-streaming chat. Returns the final response with its message, usage, and any media.
`response.usage` is the **final model call's** usage. `response.usage_total` is the sum across
every Re-Act iteration — the intermediate calls that requested tools included — so a whole run
can be metered without recomputing it from events. Both are `None` when no call reported usage.

```python
response = await agent.chat(
    "What's in this directory?",
    system_prompt="You are a DevOps assistant.",
    conversation=previous_messages,
    max_iterations=30,
)
print(response.message.content)
```

### `agent.stream(user_input, **options) → AsyncIterator[CLIverMessageChunk]`

Streaming chat. Yields content deltas and tool-call chunks as they arrive. The final
`__llm_trace__` chunk carries the run's diagnostic trace; each iteration entry includes that
call's `usage`. Streaming has no response object — call `chat()` when a run total
(`usage_total`) is needed.

```python
async for chunk in agent.stream("Write a README"):
    if chunk.content:
        print(chunk.content, end="", flush=True)
    if chunk.tool_call_chunks:
        print("\n[Calling tools...]")
```

### `await agent.run_skill(name, user_input, **options) → CLIverResponse`

Runs the Re-Act loop with a skill pinned — see [Skills](/core-concepts/skills/).

### Media Methods

`image()`, `video()`, `tts()`, `asr()`, `embed()`, and `rerank()` call the bound models directly.
Their `submit_*` variants return a `MediaJob` whose `result()` resolves when generation finishes.

### `await agent.aclose()`

Cancels and drains the media jobs the agent started, then closes the providers its bindings
built. A caller-supplied `provider=` and an injected `MCPClient` are never closed — their
builders own them. Close is idempotent and single-flight; afterwards every public entry point
raises `RuntimeError`, so build a new agent for a new event loop.

## Common Parameters

| Parameter | Description |
|-----------|-------------|
| `system_prompt` | Additional system content for this call |
| `conversation` | Previous messages for multi-turn context |
| `media` | Images/audio/video attached to the user message |
| `extra_tools` | Additional tools for this call only |
| `mcp_servers` | MCP server names to advertise and allow (`None` = all, `[]` = none) |
| `tool_filter` | Predicate to filter the advertised and executable tools |
| `options` | Wire request options (override binding defaults) |
| `max_iterations` | Max Re-Act iterations (default: 50) |
| `execution_policy` | Per-call execution policy |
| `skill_dispatch` | Advertise skill dispatch tools (default: on) |

For plain request → response use, note the single-shot contract: with `max_iterations=1`,
`skill_dispatch=False`, and no tools, the call makes **exactly one** provider request — no
skill catalogue is injected, no extra round trip happens, and AgentCore adds no follow-up
message. That is the cheapest shape for a JSON-mode style call:

```python
response = await agent.chat(
    prompt,
    options={"response_format": {"type": "json_object"}},
    max_iterations=1,
    skill_dispatch=False,
)
```

## Event Handling

Tool events and inference events have separate handlers. Attach a tool handler to the agent
(or to one call) for `tool.start`, `tool.end`, `tool.error`, and `tool.permission_denied`:

```python
from cliver_core.events import ToolEventType


async def on_tool_event(event):
    if event.event is ToolEventType.START:
        print(f"Running: {event.tool_name}")
    elif event.event is ToolEventType.END:
        print(f"Done: {event.tool_name} ({event.duration_ms}ms)")


agent = AgentCore(bindings, on_event=on_tool_event)
```

Inference events (`inference.started`, `inference.first_token`, `inference.chunk`,
`inference.tool_call`, `inference.completed`, `inference.error`) are emitted by the provider.
Attach their handler to the binding so it travels with every call that uses it:

```python
bindings = ModelBindings(
    llm=ModelBinding.llm(model="deepseek-chat", api_key="...", base_url="...", on_event=on_inference_event)
)
```

`AgentCore`'s `on_event=` receives tool events only. Each `inference.completed` event carries
that call's usage in `data["usage"]`, so per-call metering works even for runs with several
Re-Act iterations.

Handlers may be sync or async — a sync handler runs inline. **Handler exceptions are a
contract, not an accident.** They propagate unchanged on both surfaces — AgentCore never
catches or wraps them, and a raise from a tool handler is never converted into a tool-error
result. A raise on `inference.started` happens before the transport call, so a budget guard
on the binding's handler can abort a request before it is sent:

```python
def budget_guard(event):
    if event.event.value == "inference.started" and over_budget():
        raise BudgetExceeded()   # no request leaves the process
```

**Provider failures** raise `cliver_core.errors.ProviderError` from the provider boundary,
with the vendor's exception kept as `__cause__` and `retryable` set for rate limits, timeouts,
connection failures, and 5xx responses (`inference.error` reports it in `data["retryable"]`).
AgentCore re-raises it unchanged, so callers map it into their own error taxonomy.
